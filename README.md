# Сайт ТЕХ-ЭНЕРГО (teh-enerdgy.ru)

Ударные клейма (каталог), гидравлические прессы, матрицы и пуансоны, лазерная гравировка, конструктор клейма, заявки.
**PHP 8 без библиотек и без базы данных**: контент лежит в `data/*.json`, сборщик (`app/lib`) делает из него готовые HTML-страницы,
админка (`app/admin`) правит JSON и сразу пересобирает сайт. Посетитель получает обычный статический HTML.

Текущее состояние, решения и что ждём от клиента — в [HANDOFF.md](HANDOFF.md).

## Главное правило: один источник правды

- **Контент** (цены, товары, тексты, фото товаров и услуг) живёт в `data/` и `public_html/img/products|uploads` **на сервере**.
  Его правит клиент в админке. Поток: сервер → сюда (`php app/bin/deploy.php pull`).
- **Код** (шаблоны, стили, скрипты, ядро админки, картинки оформления) живёт здесь, в git. Поток: отсюда → сервер (`deploy.php push`).
  Заливка кода **никогда не трогает** `data/`, фото товаров и `storage/`.
- HTML-страницы — производные: они пересобираются после каждого сохранения в админке и после каждой заливки кода.
- **Перед любой правкой у себя — сначала `pull`**, иначе можно затереть правки клиента.
- `scripts/import-ozon.js` перезаписывает `data/products.json` целиком — после запуска админки только с `--force` и осознанно.

## Где что

| Что | Где |
|---|---|
| Факты о компании (телефон, почта, адрес, реквизиты, рейтинг) | `data/company.json` (правится в админке) |
| Каталог: категории и товары | `data/products.json` (правится в админке; фото — `public/img/products/<артикул>/N.webp` 750×1000 и `N-s.webp` 300×400) |
| Пресс, гравировка, матрицы | `data/press.json`, `data/laser.json`, `data/matrix.json` (правятся в админке; загруженные фото — `public/img/uploads/`) |
| Вопросы-ответы, описания категорий | `data/site.json` |
| Шаблоны страниц | `app/lib/pages.php` (страницы), `app/lib/render.php` (оболочка, шапка, подвал, формы, карточка) |
| Сборка и запись файлов | `app/lib/build.php`, `app/lib/fs.php` |
| Какие поля есть в админке | `app/admin/schema.php` — добавить поле = одна строка (+ вывод в шаблоне) |
| Сохранение, проверка значений, операции | `app/admin/content.php`, `app/admin/ops.php` |
| Интерфейс админки | `app/admin/ui/` (`admin.js`, `admin.css`) |
| Приём заявок | `public/send.php` → `app/lead.php`, отправка — `app/lead-deliver.php` |
| Стили и скрипты сайта | `public/css/style.css`, `public/js/main.js` |
| Сырая выгрузка Ozon | `data/ozon_raw.json`, `scripts/import-ozon.js`, `scripts/download-images.js` |

## Команды (на своём компьютере)

Нужен PHP 8.1+ с `gd` (WebP), `mbstring`, `curl`, `ftp`, `exif`.

```bash
php app/bin/build.php                      # собрать сайт в dist/
php -S 127.0.0.1:8090 app/dev-router.php   # сайт http://127.0.0.1:8090, админка /admin/, заявки /send.php
php app/bin/admin-setup.php <пароль>       # создать вход в админку локально
node tests/roundtrip.mjs                   # каждый раздел и товар сохранить без изменений → «Изменений нет», git status data чистый
node tests/edits.mjs                       # правки, откат, корзина, фото, заявка с файлом; потом: git checkout data && git clean -fd public/img
```

Локальные настройки — `app/config.local.php` (в git не хранится): `'admin_local_no_gate' => true` — на 127.0.0.1 без секретного адреса.

## Админка

Адрес входа: `https://teh-enerdgy.ru/admin/<секретное-слово>` → пароль. Без секретного адреса любой `/admin/...` отвечает обычной 404.

- **Товары каталога**: цена, старая цена (скидка), названия, категория, характеристики, рейтинг, фото (загрузка с обрезкой до 3:4, порядок, главное фото), порядок в каталоге, «скрыть с сайта», добавить новый (свой артикул с 9000000001), удалить в корзину.
- **Категории каталога**, **компания и контакты** (ссылка `tel:` пересчитывается из телефона сама), **вопросы и ответы**.
- **Пресс**, **лазерная гравировка**, **матрицы и пуансоны**: тексты, цены, сроки, карточки услуг и работ с фото.
- **Заявки** — все заявки с форм сайта, прикреплённый файл скачивается из админки. **История правок** — вернуть любую версию. **Корзина** — удалённые товары с фото. **Настройки** — куда слать заявки (почта, Telegram), смена пароля.

Если сохранение ломает сборку — файлы возвращаются как были и админка показывает ошибку, сайт не ломается.
Например, нельзя скрыть или удалить товар, на который ведёт 301-редирект со старого сайта.

## Хранилище `storage/` (не в git, с сервера не забирается)

Пароль и секретное слово (`admin.json`), сессии, счётчик попыток входа, заявки и вложения (`leads/`), история правок (`revisions/`),
корзина (`trash/`), настройки отправки заявок (`settings.json`). Сброс пароля: `php app/bin/admin-setup.php <новый-пароль>` по SSH
или удалить `storage/admin.json` и сделать новый вход (см. `deploy.php init`).

## Публикация на Beget

Раскладка на сервере (FTP `tehenem8.beget.tech`, папка `teh-enerdgy.ru/`):

```
app/          ядро (из репозитория)
data/         контент — единственный источник правды
storage/      создаётся сама
public_html/  корень сайта: статика + собранные страницы; из PHP там только заглушки admin/index.php и send.php
```

Доступ — `app/deploy.local.php` (пример `app/deploy.example.php`), настройки сервера — `app/config.server.php`
(пример `app/config.server.example.php`, в нём `deploy_key` — тот же, что в `deploy.local.php`). Оба файла в git не хранятся.

```bash
php app/bin/deploy.php init <пароль>  # первая установка: код, данные, фото, настройки сервера, вход в админку (на сервер без data/)
php app/bin/deploy.php push --dry     # что уедет
php app/bin/deploy.php push           # залить изменённый код и пересобрать сайт на сервере
php app/bin/deploy.php pull           # забрать правки клиента (data/ и фото) и закоммитить
```

`init` не заливает повторно фото и видео, которые уже лежат на сервере с тем же размером. На сервер с существующими `data/` не пойдёт.

## Перенос со старого сайта (Tilda) без потери позиций

Домен тот же, поэтому «переезд сайта» в Вебмастере **не нужен**: главное зеркало остаётся `https://teh-enerdgy.ru` (без www, как было).
Вес старых страниц передают 301-редиректы в `public/.htaccess`, каждый сразу на конечный https-адрес, без цепочек:

- страницы: `/politic` → `/politika/`, `/sogl` → `/soglasie/`, `/catalog` → `/catalog/`, `/thanks` и служебные страницы Tilda → главная, `/sitemap-store.xml` → `/sitemap.xml`;
- 29 товаров магазина Tilda (`/catalog/tproduct/<id>-…`, список из старого `sitemap-store.xml` на 15.10.2026) — по id на ту же позицию в новом каталоге, на страницу услуги гравировки или на `/matricy/`; товары без аналога (АС, НАКС, клеймо для заклёпок) — в каталог, снятое оборудование (сопла, термопресс, лазеры) — на главную;
- `www.` и `/index.html` → основной адрес.

Сборка падает с ошибкой, если редирект ведёт на страницу, которой нет (в админке такое сохранение не пройдёт). Если меняется адрес страницы (slug клейма или услуги), поправить и `.htaccess`.

После переключения:
1. Проверить редиректы: `curl -sI https://teh-enerdgy.ru/catalog/tproduct/579072598632-kleimo-otk5-10-100` — `301` и `Location` на новую страницу; так же `http://`, `www.`, `/politic`.
2. Вебмастер: «Индексирование → Файлы Sitemap» — удалить `sitemap-store.xml`, добавить `https://teh-enerdgy.ru/sitemap.xml`; «Переобход страниц» — главная, `/catalog/`, `/pressy/`, `/matricy/`, `/gravirovka/`.
3. Если права в Вебмастере были подтверждены файлом Tilda — положить его в `public/`, мета-тег — в `layout()` в `app/lib/render.php`.
4. Две–четыре недели смотреть в Вебмастере ошибки 404 и «Исключённые». Редиректы не удалять минимум год.
